## Сравнение векторных баз данных

### 1. FAISS
**Разработчик:** Meta AI  
**Язык реализации:** C++ / Python  
**Описание:** Библиотека поиска по приближённым ближайшим соседям (ANN) для высокоразмерных векторов.  
Поддерживает как CPU-, так и GPU-индексацию, легко интегрируется в LangChain и другие Python-фреймворки.

**Преимущества:**
- Высокая скорость индексации и поиска (до миллионов векторов в секунду на GPU).
- Простота использования в Python-проектах и хорошая совместимость с LangChain.
- Возможность локального развёртывания без дополнительных сервисов — идеально для on-prem решений.
- Бесплатна и открыта (open-source), без постоянных расходов на инфраструктуру.
- Поддерживает различные типы индексов (Flat, IVF, HNSW, PQ) — можно адаптировать под объём данных и доступное железо.

**Недостатки:**
- Не хранит метаданные документов — их нужно реализовать отдельно (например, в SQLite или PostgreSQL).
- Нет встроенного REST-API — взаимодействие идёт через Python.
- Требует ручного резервного копирования индекса и мониторинга состояния.

### 2. ChromaDB
**Разработчик:** Chroma Team  
**Язык реализации:** Python  
**Описание:** Современная векторная база для RAG-решений, ориентированная на удобство разработчика.  
Поддерживает хранение метаданных, персистентность и API-доступ.

**Преимущества:**
- Встроенное хранение метаданных, простое API и интерфейс для LangChain.
- Есть облачная версия (Chroma Cloud) — минимум настроек для быстрого старта.
- Поддерживает фильтрацию, теги и постоянное хранение векторов.

**Недостатки:**
- Ниже производительность при работе с очень большими индексами.
- Менее гибкая конфигурация алгоритмов поиска.
- Для локального режима требует дополнительного сервисного слоя и хранения данных на диске.
- В корпоративной среде может потребовать аудит безопасности из-за дополнительных зависимостей.

## Вывод и рекомендации

Для проекта QuantumForge Software рекомендуется использовать **FAISS** в качестве векторной базы данных.

### Обоснование выбора
1. **Безопасность данных:** индекс и векторные представления хранятся локально, что важно при работе с конфиденциальной корпоративной документацией.  
2. **Производительность:** FAISS обеспечивает наилучшее время отклика и поиск даже по десяткам тысяч документов.  
3. **Интеграция с LangChain:** готовые классы `FAISS.from_documents()` и `FAISS.load_local()` позволяют быстро построить RAG-пайплайн.  
4. **Низкая стоимость владения:** не требует дополнительных сервисов или подписок — достаточно Python-окружения.  
5. **Простота поддержки:** индекс можно хранить в Docker-томе или отдельной директории и восстанавливать при перезапуске.
