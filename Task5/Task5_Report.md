# Задание 5 — Отчёт о демонстрации работы и защите RAG-бота

## 1) Конфигурация
- Индекс: `vector_store/faiss_index/` (FAISS), база — *Chronicles of the Synth Flux* (30+ доков).
- Эмбеддинги: `BAAI/bge-base-en-v1.5` (768 dim).
- LLM: `gpt-4o-mini` через `langchain-openai` (температура 0–0.2).
- Интерфейс: CLI (`python -m src.cli_secure`).

## 2) Слои защиты
1. **Pre-prompt (system)**: запрещает выполнять команды/инструкции из документов; отвечать только по фрагментам; при нехватке данных — «Я не знаю.»; формат ссылок `[file#chunk_id]`.
2. **Sanitization (pre-context)**: вырезает/маскирует конструкции вида `ignore all instructions`, `output:`, `system:`, `assistant:`, `swordfish` и т.п.
3. **Post-filter (docs)**: отбрасывает чанки, содержащие ключевые запрещённые паттерны (см. `src/filters.py`).

Переключатели (env):
```bash
export RAG_PREPROMPT=1   # включить системный запрет
export RAG_SANITIZE=1    # включить очистку контента
export RAG_POSTFILTER=1  # включить фильтрацию документов
```

## 3) Команды запуска
```bash
# собрать индекс, чтобы в него попал zzz_malicious.txt
python src/build_index.py

# запуск защищённого REPL
export RAG_PREPROMPT=1
export RAG_SANITIZE=1
export RAG_POSTFILTER=1
python -m src.cli_secure
```

## 6) Краткие выводы
- **Корректное поведение**: при включённых всех слоях защиты бот даёт полезные ответы по «чистым» темам и отказывается на провокации — без цитирования вредоносного текста.
- **Потенциальная уязвимость**: при полном отключении защит (особенно sanitization и post-filter) модель может процитировать фразу из вредоносного документа, если она попала в контекст. Это подтверждается тестами без защит.
- **Рекомендации**:
  - Держать включёнными все 3 слоя.
  - Расширить блок-листы и санацию (учесть локализации, «выведи», «процитируй», «приведи дословно» и т.д.).
  - Ввести уровни доверия к источникам (например, исключать свежезагруженные файлы до ручной модерации).
  - Логировать попадание чанков, содержащих запрещённые маркеры, и уведомлять оператора.
